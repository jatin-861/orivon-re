## SEO.tsx Component

`src/components/SEO.tsx` — renders per-page metadata using React 19's document metadata hoisting.

**Props interface:**

```tsx
interface SEOProps {
  title?: string;
  description?: string;
  keywords?: string;
  canonical?: string;
  ogUrl?: string; // falls back to canonical if not provided
  ogTitle?: string; // falls back to title
  ogDescription?: string; // falls back to description
  ogImage?: string;
  ogType?: string; // default: "website"
  twitterCard?: string; // default: "summary_large_image"
  twitterSite?: string;
  twitterCreator?: string;
  schema?: Record<string, unknown> | Record<string, unknown>[]; // single or array
}
```

**Schema injection pattern:**

```tsx
// Single schema
<SEO schema={{ "@context": "https://schema.org", "@type": "WebSite", ... }} />

// Array of schemas (about page — two Person schemas)
<SEO schema={[personSaral, personJatin]} />
```

Schemas are serialized via `JSON.stringify` into `<script type="application/ld+json">` tags.

## Static Schemas (index.html)

Two schemas are embedded directly in `index.html` as static `<script>` blocks before `</head>`:

1. **WebSite** — `@type: "WebSite"` with name, url, description, publisher
2. **Organization** — `@type: "Organization"` with name, url, description, areaServed, contactPoint, sameAs (two GitHub URLs), member array (two Person objects)

These are the only schemas guaranteed visible to non-JS crawlers. See Decision D-005.

**Important:** When updating canonical titles or contact information, update `index.html` AND the dynamic schemas in `about.tsx`.

## Dark Mode Script (index.html)

The dark-mode inline script must appear as the very first element inside `<head>`, before any CSS or other scripts, to prevent flash of wrong theme:

```html
<script>
  (function () {
    try {
      var theme = localStorage.getItem("theme");
      if (theme !== "light") document.documentElement.classList.add("dark");
    } catch (e) {
      document.documentElement.classList.add("dark");
    }
  })();
</script>
```

## llms.txt

Location: `/public/llms.txt`  
Format: Plain text, section headers with `##`, bullet items with `-`

**Mandatory sections:**

- Identity (studio name, type, location, contact)
- Founders (name, role, GitHub per person)
- Production Systems (all projects with stack, metrics, repos)
- Services (service categories)
- Key Facts (proof metrics)
- Pages (all routes with descriptions)

**Update trigger:** When a new project is added, a new founder joins, or key metrics change.

## Schema Validation

Use Google's Rich Results Test or Schema.org validator to verify schemas after changes.

Static schemas in `index.html`: validate by viewing page source (not rendered DOM).  
Dynamic schemas via SEO.tsx: validate via browser devtools → Elements → `<script type="application/ld+json">`.
